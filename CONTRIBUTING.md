# Contributing to SAATHI (साथी)

Thank you for contributing to **SAATHI**, an AI-guided vocational guidance platform for rural households developed for the Smart India Hackathon 2026 (Problem Statement 262241).

To maintain high code quality, accessibility, and cultural resonance for rural Indian users, all contributors must follow the conventions outlined below.

---

## 1. Monorepo Structure & Build Order

SAATHI is configured as an npm workspaces monorepo:

```
├── packages/
│   └── shared/          # Shared Zod schemas, TypeScript types, and domain DTOs
└── apps/
    ├── api/             # Express.js REST API with Prisma ORM (PostgreSQL)
    └── web/             # Vite + React 18 + TailwindCSS + Hearth Design System
```

### Critical Monorepo Dependency Rule:
`@saathi/shared` outputs compiled JavaScript and type declarations to `packages/shared/dist/`. 
Whenever you modify files in `packages/shared/src/`, you **must rebuild the shared package** before running API tests or starting servers:

```bash
npm run build --workspace=@saathi/shared
```

---

## 2. Branching Strategy

- **`main`**: Production-ready branch. All commits on `main` must pass all linting, typechecking, Vitest tests, and Playwright suites.
- **`feat/<feature-name>`**: New features (e.g., `feat/voice-search`, `feat/offline-queue`).
- **`fix/<bug-name>`**: Bug fixes and patches (e.g., `fix/header-overflow-320px`).
- **`chore/<task-name>`**: Tooling, dependencies, or documentation cleanups.

---

## 3. Commit Message Conventions

We strictly follow the [Conventional Commits specification](https://www.conventionalcommits.org/):

| Prefix | Usage | Example |
| :--- | :--- | :--- |
| `feat:` | Adding a new user-facing feature | `feat: add 16 kbps audio fallback for rural 2G WebRTC` |
| `fix:` | Correcting a bug or runtime failure | `fix: prevent k-anonymity suppression leak on single-household buckets` |
| `style:` | UI formatting, design system, CSS adjustments | `style: replace pill buttons with Hearth rounded-lg geometry` |
| `test:` | Adding or modifying unit, integration, or e2e tests | `test: add Playwright responsive overflow audit for 320px viewport` |
| `docs:` | Creating or editing documentation files | `docs: document Bhavishya engine alignment score formula` |
| `chore:` | Build scripts, dependencies, configuration | `chore: remove duplicate progress markdown tracking file` |

## 4. Code & Design Guidelines

### A. Hearth Design System Rules (Strictly Enforced)
1. **No Purple Colors**: Do not use purple, violet, `#7c3aed`, or related shades. Use the Hearth earthen palette:
   - Primary Terracotta: `var(--color-primary)` (`#C4562B`)
   - Student Marigold: `var(--color-student)` (`#EFA531`)
   - Parent Leaf: `var(--color-parent)` (`#2F7D5C`)
   - Earthen Dark/Text: `var(--color-text)` (`#3A2E2A`)
2. **No Pill Buttons**: Buttons must use rounded rectangular geometry (`rounded-[8px]`, `rounded-lg`, or `rounded-xl`). Never use `rounded-full` on clickable action buttons.
3. **No Raw Emojis in Source Code**: Do not include raw unicode emoji characters (e.g., `✅`, `⚠️`, `🚀`) in `.ts` or `.tsx` files. Use [Lucide React](https://lucide.dev) icons or localized string keys.

### B. Clean Code & Zero-Attribution Standards
1. **No Production `console.log`**: Production code must not include stray `console.log` statements. Use structured Pino logging in the API (`logger.info`, `logger.warn`, `logger.error`).
2. **No TODOs / FIXMEs**: Do not leave unaddressed `TODO`, `FIXME`, `HACK`, or `XXX` comments in committed code. Implement the full feature or document the limitation in architecture notes.
3. **No AI Attribution Tags**: Code files must not contain "Generated by", "AI-generated", "ChatGPT", or similar generator watermarks.

### C. Bilingual & Rural Inclusivity Requirements
1. **Every User-Facing String Must Be Localized**: Both English (`apps/web/src/locales/en.json`) and Hindi (`apps/web/src/locales/hi.json`) keys must be added for every new label, tooltip, error, or toast message.
2. **Median Over Average**: Always present median salaries (`medianSalaryStarting`, `medianSalaryAfter3Yrs`), never averages, to resist outlier skew from elite urban roles.
3. **Lite Mode Compatibility**: Every new UI component must render gracefully under `.lite-mode` (no background gradients, zero layout shifts, no heavy decorative SVGs).

## 5. Pre-Pull Request Verification Checklist

Before submitting a Pull Request or pushing commits to `main`, verify all checks pass:

```bash
# 1. Format check
npm run format:check

# 2. Lint check (zero ESLint errors)
npm run lint

# 3. TypeScript compilation across all workspaces
npm run typecheck

# 4. API & Web Vitest test suites (179 tests)
npm test

# 5. Playwright E2E smoke & responsive audit (25 tests)
npm run test:e2e

# 6. Dead code and unused dependency audit
npm run knip

# 7. Production bundle build
npm run build
```

---

## 6. Code Review & Definition of Done

A PR is only approved when:
- [ ] All 204 automated tests pass without warnings or flaky retries.
- [ ] No horizontal overflow is introduced at 320px, 375px, 768px, or 1280px viewports.
- [ ] Both English and Hindi translations are complete and accurate.
- [ ] Database schema changes include Prisma migrations and seed updates.
- [ ] `PROGRESS.md` reflects any newly completed milestones and architectural decisions.
